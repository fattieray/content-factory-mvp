## 十、回滚方案

### 10.1 回滚触发条件

出现以下情况立即回滚：

- 核心功能不可用 > 10 分钟
- 数据丢失或损坏
- 安全漏洞
- 错误率 > 20%

### 10.2 回滚步骤

**前端回滚**：
```bash
# Vercel 回滚到上一版本
vercel rollback --yes
```

**后端回滚**：
```bash
# Railway 回滚
# 1. 进入 Railway Dashboard
# 2. 选择 Deployments
# 3. 点击上一版本的 Promote
```

**数据库回滚**：
```bash
# 从备份恢复
# 1. 停止应用
# 2. 恢复备份
# 3. 验证数据
# 4. 重启应用
```

### 10.3 回滚验证

- [ ] 回滚后功能验证
- [ ] 数据完整性检查
- [ ] 用户通知（如影响）

2. 判断是否代码问题

4. 如否，排查依赖服务

1. 检查数据库状态
2. 检查连接池配置
3. 重启数据库服务
4. 如数据损坏，从备份恢复

1. 检查 AI API 状态
2. 检查队列积压
3. 增加 Worker 数量
4. 启用降级策略
